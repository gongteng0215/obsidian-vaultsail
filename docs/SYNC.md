# 0.1.10 同步机制与冲突保留

主工具栏云朵图标和「开始同步」按钮现在执行双向同步；旧版该图标实际打开单向上传预览。按钮仍需用户手动触发，不设置后台定时任务。

## 常见变更

| 情况 | 行为 |
|---|---|
| 只有本地改动，云端仍是上次基线 | 自动上传 |
| 只有云端改动，本地仍是上次基线 | 校验、备份后自动下载应用 |
| 内容相同 | 跳过传输并确认基线 |
| 双方改动、首次同名不同内容、多个有效分支 | 自动保留双方副本与云端分支 |
| 删除传播关闭 | 不传播删除 |

单向上传/下载也使用已验证基线识别正常更新。单向下载保留冲突时不会把本地内容上传到云端。

## 双方同时修改

插件先把有效远端内容下载并验证，再保存可见副本。副本位于本地 `VaultSail-conflicts/`，文件名带来源设备/版本标识，目录强制排除同步。

本地有独立改动时保留原笔记，并将本地版本以独立分支发布；不会把所有竞争父版本合成一个伪造的“已解决”版本。本地没有改动时，保留全部有效内容后按版本 ID 稳定选择一个远端版本作为原笔记的显示内容。设备时间不用于决定谁覆盖谁。

重复同步不新增相同内容的分支，也不反复制造相同副本。用户编辑过的副本会保留，必要时用新文件保存原版本。首次绑定的空设备也能取得原笔记和全部竞争内容。

冲突保留属于自动同步的一部分，不需要点击“解决”才能继续传输其他正常文件。若希望最终把原笔记统一为某一个内容，可使用预览中的「可选：统一为所选版本」。正文语义合并仍由用户决定；本版不自动把两篇笔记的文字拼接。

## 恢复与验证边界

自动冲突分支的上传仍记录原操作 ID，内容先于记录发布。中断恢复检查实际远端内容、父版本和本地状态；已有有效副本和原笔记不会被直接覆盖。

81 项自动化测试包含普通更新、并发分支、副本编辑、空设备下载、重复同步、发布前中断、批次中出现新的远端版本，以及缓存损坏后的真实读取回退。真实百度限流、实际 iPad、设备挂起和长时间运行仍需设备验收。
