# 0.2.18 本地预览 · 远程读取性能

本轮针对重复读取云端历史导致的等待，不改变云端格式、授权、绑定、文件上限或并发设置。

## 现场证据与判断

本机已有数字化性能摘要显示：连续多轮任务均为 81 次网络请求、49 条历史正文读取、缓存命中 0、缺少可用指纹 49；令牌刷新与重试均为 0，单轮约 14–20 秒。首先需要解决缓存失效与重复下载。旧日志未保留远端摘要原值，不能仅据此确认该账号实际返回的摘要格式。

代码将百度 `md5` 字段限定为十六进制串。使用含非十六进制字符的 32 位服务端摘要可复现同类缓存失效，现已兼容该不透明变更指纹。它只用于判断版本变化，正文仍以 SHA-256 校验；缺失、格式异常或变化的指纹继续触发读取与核验。

## 改动

- 修复不透明服务端摘要导致的文件、目录及库元数据缓存失效。
- 持久目录缓存按账号、应用目录、库和设备隔离；重启或再次打开远程列表可复用。损坏缓存回退读取，保存失败不影响同步，无变化不重写缓存。
- 远程列表并行读取文件与目录版本，继续共享当前请求上限。
- 文件和目录均无变化时，复用本轮已完整枚举的目录计划；有变更、删除、恢复或本地目录变化时继续核验。
- 诊断增加各摘要格式的数字计数，不保存摘要原值或响应正文。
- 目录版本读取同样限定为 1 MiB 元数据上限。

## 模拟对比

固定 49 篇笔记、7 条目录记录、两个文件操作设备目录，返回不透明摘要；0.2.17 基线与当前实现各跑 3 轮，每次模拟请求延迟 3 ms。

| 场景 | 旧版请求数 | 新版请求数 | 历史文件/目录正文下载次数 |
| --- | ---: | ---: | --- |
| 无变化再次同步 | 79 | 8 | 63 → 0 |
| 重启后同步 | 79 | 10 | 63 → 0 |
| 打开远程列表 | 68 | 10 | 56 → 0 |

另覆盖 100 篇笔记，以及 1000 篇笔记的单轮规模检查。首次无缓存仍需读取历史，不能承诺固定秒数；模拟比较请求开销，不代表真实百度吞吐。见 [数字报告](../benchmarks/0.2.18-remote-cache.json)。

复现：`node --experimental-strip-types scripts/benchmark-remote-cache.mjs baseline 49 3`，然后将 `baseline` 改为 `current`。夹具不连接真实账号。

## 本机验收

259 项自动化测试通过，覆盖非十六进制指纹、真正缺失指纹、同大小内容变化、重启缓存、损坏和保存失败、新设备目录发现、无变化计划复用与诊断脱敏。保留现有删除、冲突、恢复及界面测试。

更新后关闭再启用插件，先同步一次建立缓存，再连续同步比较请求数与缓存命中。真实百度首次/再次/重启耗时和大附件下载速度仍待复测；本次仅本地预览，尚未发布社区。

## English

This preview fixes history cache misses when a server digest is an opaque 32-character token rather than hexadecimal MD5. It remains a change fingerprint; content verification still uses SHA-256. Directory caches survive reloads, remote file/directory inventories load concurrently, and unchanged tasks reuse their completed directory scan. Destructive actions retain fresh verification. Missing fingerprints require reads; cache failures remain advisory. Numeric diagnostics distinguish digest formats without retaining their values. Synthetic request reductions are not a measurement of live Baidu throughput.
