# VaultSail 0.1.20 测试版

将独立文件从逐个传输改为默认 3 路并发上传/下载，首次读取云端历史也并发执行。设置中的「同时传输的文件数」支持 1–4 路，当前设备独立保存，修改不解除授权、库绑定或已有预览。实时进度显示同时工作的文件数，读取历史时显示已验证的版本记录数。

文件的恢复意图先保存，再发起并发网络请求；内容与操作记录仍完整回读校验。本地文件写入、恢复日志和基线提交排队执行，完成时只移除本操作日志。某一路失败或暂停后停止后续批次，等待已发出的请求结束；保留未完成操作 ID，恢复时核验实际结果，防止重复发布。冲突、删除及重命名仍在独立文件批次之间依次处理。

默认并发 3、最多 4；每批按 24 MiB 估算内容预算减少同时处理的大附件数量，单文件上限仍为 20 MiB。此预算不等于进程内存上限，完整缓冲区及协议处理仍占额外内存。相同内容对象的并发写入共享一个上传，公共目录创建合并等待，避免重复提交。

124 项自动化测试、类型检查、构建及 ZIP 校验通过，覆盖 3/4 路限宽、串行本地写入/日志提交、失败后等待其他请求收尾、响应丢失和暂停后的原 ID 恢复、状态保存失败保留多个日志、下载时本地编辑不覆盖、大附件降并发、相同内容合并上传及历史并发读取。

合成延迟对比：12 个 1 KB 文件，每次模拟读/写延迟 20 ms，每组 3 次平均，全部文件 Hash 一致。上传 1303 ms → 463 ms（约 2.81 倍），下载 797 ms → 298 ms（约 2.67 倍）。这是模拟接口收益，不能代替真实百度带宽、限流及 iPad 内存验收；[原始结果](../benchmarks/0.1.20-concurrency.json)与[复现说明](../PERFORMANCE.md)已保留。

最低 Obsidian 1.11.4，云端存储格式和旧有效配对码兼容；仅发布 GitHub 测试版，社区更新继续等待真实设备验证。
