# 0.2.9 — 扫描性能本地预览 / Local scan performance preview

本版先在本机验收，尚未发布社区。最低 Obsidian 1.11.4。包含此前传输中心、分片并发和紧凑布局；无需重新授权、导出配置或绑定库。

## 行为变化

- 冷扫描只为未命中缓存的记录准备读取信息，每个窗口最多 100 条；准备后立即以现有并发读取。有效链接复用，过期后重新准备；下载地址只在提供器内短期保存。
- 完整枚举设备目录后，最多并行读取 4 个设备的记录目录；每个目录内分页仍依次推进，并继续受用户配置及共享请求上限约束。
- 缓存条目、指纹和有效目录集合没有变化时，不重新序列化或写入版本缓存。保存失败不改变同步判断，下次扫描重试保存。
- 紧凑状态区显示目录进度、发现的版本数、缓存命中、实际读取和版本校验阶段。总数未确定时不用虚假百分比；等待请求空位和接口繁忙分别提示。
- 最近 30 次本机任务可保存固定字段的数字性能摘要，重启后可在同步历史及传输中心查看。在「传输与恢复 → 实验功能与诊断」点击「复制性能报告」导出版本、平台、计数和耗时，不包含路径、账号、URL、凭据或笔记正文。旧历史照常读取，损坏摘要忽略。

每轮仍重新枚举完整远端目录。手动同步保留完整本地内容核验，自动任务沿用原有增量检查。缺失指纹仍下载验证；元数据身份、大小或已知摘要变化会停止本轮扫描。保留父版本、分页、未知写入核验和写入后复查。没有新建云端索引或更改云端格式。

## 模拟基准

基线为 0.2.8 的 `60d494a`。相同百度接口模拟器，每请求注入 2 ms 延迟（实际定时器调度受宿主系统影响），读取并发 8；每组单设备重复 10 轮，测量完整手动同步，包含账号检查及本地完整 Hash。云端列表提供 MD5。所有文件内容都是合成数据。

| 文件数 | 首次同步总请求：前 → 后 | 下载元数据请求：前 → 后 | 首次同步中位数：前 → 后 | P95：前 → 后 |
| --- | --- | --- | --- | --- |
| 7 | 20 → 14 | 8 → 2 | 122.4 → 123.7 ms | 156.1 → 143.6 ms |
| 100 | 207 → 108 | 101 → 2 | 502.4 → 318.3 ms | 510.8 → 326.6 ms |
| 1000 | 2016 → 1026 | 1001 → 11 | 4076.7 → 2420.3 ms | 4106.2 → 2505.6 ms |

1000 文件首次请求减少约 49.1%，该模拟总耗时中位数减少约 40.6%。7 文件中位数基本持平；批量准备更明显地帮助记录较多的冷扫描，并不保证所有任务更快。

| 无变化热同步 | 总请求（前后相同） | 历史正文读取（前后相同） | 缓存写入：前 → 后 | 中位数：前 → 后 |
| --- | --- | --- | --- | --- |
| 7 文件 | 4 | 0 | 1 → 0 | 61.1 → 61.4 ms |
| 100 文件 | 5 | 0 | 1 → 0 | 77.4 → 76.7 ms |
| 1000 文件 | 14 | 0 | 1 → 0 | 259.0 → 250.8 ms |

1000 文件热同步 P95 为 278.7 → 295.8 ms，存在调度波动，不能声称各分位都改善。重启后仍需读取一次库元数据，但历史记录可从已验证持久缓存复用；无变化时不写缓存。手动同步的本地全量核验未减少。

补充 4 设备、100 文件、各 3 轮：首次请求 209 → 110，中位数 527.1 → 310.0 ms；无变化请求均为 7，中位数 108.8 → 61.2 ms。独立目录等待可重叠，不代表百度真实限流和网络表现。

另记录本地单文件修改、远端修改和并发发布；远端内容应用后 Hash 相同，两个并发分支都能发现。并发发布场景只扫描分支，不计入冲突解决。随机 UUID 的窗口分布可能使单文件/并发场景的元数据计数随轮次变化，详见 [原始逐轮结果](../benchmarks/0.2.9-scans.json)。

复现：`node --experimental-strip-types scripts/benchmark-scan-preview.mjs --sizes 7,100,1000 --rounds 10 --latency 2`。`--side baseline` 或 `--side current` 可单独运行，`--devices 4 --sizes 100 --rounds 3` 为多设备补充。模拟对比不能代替真实百度速度验收。

## 验证与本机步骤

207 项自动化测试、类型检查、生产构建和 ZIP 内容/版本一致性检查通过。

回归覆盖 100 条准备窗口、多页枚举、最多 4 设备并行及配置 1 路、首次/热缓存/重启、无摘要回退、缓存损坏和保存失败、身份/摘要变化、链接过期、分页失败收尾、一万条边界及超限阻断、性能摘要白名单和历史重启。原有并发编辑、重命名、冲突、暂停、重载和写入结果未知用例继续执行。

重新启用插件后，在同一测试库连续同步两次，再重启插件同步，最后在另一设备修改一篇笔记并检查接收。可复制性能报告对比扫描次数、请求和缓存写入。无需提供密钥或笔记正文。原生 Windows/iPad 界面、真实百度速度及长期双端可靠性仍待用户设备验收。

文件并发默认 8、范围 1–32；电脑分片默认 2、范围 1–4，移动端 1；电脑最高 512 MiB、移动端 20 MiB；仍是完整缓冲。已有自动同步、检查间隔和删除选择保留。

## English

Local preview only; requires Obsidian 1.11.4+. Revision downloads are prepared in windows of up to 100, device directories are listed with at most four concurrent workers under the existing request budget, and unchanged revision caches are not serialized or rewritten. Full directory discovery, local manual verification, parent validation, pagination and uncertain-write checks remain. Cloud and pairing formats are unchanged.

The compact UI shows scan phases and real discovery counts. Numeric performance summaries persist with the last 30 local tasks; the performance report button exports only whitelisted version/platform/counter/timing fields. Older history remains readable and invalid summaries are ignored. All 207 automated tests, type/build and package checks pass.

Against 0.2.8, ten-round synthetic 1000-note cold sync reduces requests from 2016 to 1026 and median duration from 4076.7 to 2420.3 ms. Warm sync retains 14 requests and zero revision downloads, while cache writes fall from one to zero. Seven-note median time is effectively unchanged, and warm P95 varies. These are mock API results with injected latency, not real Baidu throughput or native-device certification. See the tables and raw report above. Re-enable the plugin, compare consecutive/restarted sync, then verify another device's edit locally.
