# 0.2.15 本地预览 · 可追溯的排错记录

本轮重点是记录证据，不将此前某次未知异常宣称为已经定位或修复。升级不改变云端格式、授权、绑定、同步判断或原有设置。

- 新增本机诊断记录器，关联任务、请求、文件、历史记录和恢复操作。
- 保留四层错误原因链，记录固定步骤、系统/HTTP/百度错误码、调用位置和匿名签名。
- 记录并发、大小、删除与增量检查设置、分片里程碑、重试等待及成功保存的恢复阶段。
- 失败和常规记录分别轮转，最多七天、各十六段，合计约 4 MiB；日志失败不阻断同步。
- 报错和逐文件记录带诊断编号；设置/命令面板提供查看、按编号筛选、复制和文件导出。
- 报告使用白名单，不保存原始异常消息、请求/响应正文、路径、凭据或笔记正文。
- 生产构建独立归档源码映射；提供构建/Hash 核验后还原调用位置的工具。

方案、边界、保存位置和复现流程见 [排错日志设计](../DIAGNOSTIC_LOGGING.md)。旧版未记录的异常无法补录；强制结束进程时未落盘的尾部记录可能丢失。真实 iPad 存储与现场失败回归仍需验证。

本轮 234 项自动化测试、类型检查、生产构建及三文件 ZIP 检查通过。新增覆盖原因链、日志恢复/轮转、磁盘故障、敏感数据样本、迟到请求、重复批次、诊断编号、构建映射以及界面导出；完整结果保存在本机 `dist/test-results-0.2.15.txt`。这些结果不是实际百度故障或 iPad 存储验收。

Local preview adds correlated structured diagnostics, bounded local retention, safe cause chains and stack positions, per-file diagnostic references, an explicit report export UI, and build-matched stack resolution. No credentials, paths, raw messages, request/response bodies or note contents are persisted. Logging failures cannot replace sync recovery decisions. This document does not claim community publication or native iPad acceptance.
