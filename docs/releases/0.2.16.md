# 0.2.16 本地预览 / Local preview

空文件夹现在有独立的目录版本，可通过手动上传、下载和自动队列同步。预览清单、传输记录与云端树形列表均显示目录；没有创建占位笔记。

Empty folders now have their own immutable directory revisions and participate in manual upload/download and the automatic queue. Plans, transfer history and the cloud tree display directories without placeholder notes.

## 使用与兼容 / Usage and compatibility

- 两端都安装 0.2.16 或更新版本，绑定同一云端库后同步。无需重新授权、导出配置或绑定。
- 多层目录发布至 `directories/<deviceId>/<opId>.json`。另一设备同步后创建正常目录。网盘仍是插件管理的版本存储，并非笔记目录镜像。
- 旧版忽略新的目录记录，继续读取原有 `ops/` 文件版本；旧版不会同步空目录。没有更改 `vault.json`、文件操作记录或配对格式。
- 删除沿用已有开关，默认关闭。本机删除且云端版本未变时，不强制重建该目录。开启后记录删除，只移除空目录；父目录在子目录之后处理，新增笔记会阻止移除。
- 创建与删除并发时优先保留目录，合并记录引用各父版本，不以设备时间选胜方。
- 目录重命名表现为新路径创建与旧路径删除。旧路径删除仍需开启删除传播，且目录必须为空；文件重命名由已有文件流程处理。
- 保存恢复意图后才执行操作，提交响应丢失时沿用原操作 ID；恢复失败可保留日志排查，或使用“结束旧任务并重新预览”。
- 一次最多扫描一万条目录记录、本机一万个目录；失败分页、缺失已知版本、未知格式或路径冲突都会停止处理。

Both devices need 0.2.16 or later for empty-folder sync. Existing authorization, binding, file records and pairing formats are preserved. Older clients continue file sync and ignore the separate `directories/` namespace. Deletion remains opt-in and removes only empty local folders, using a nonrecursive filesystem operation. Concurrent creation wins over deletion without comparing timestamps. Directory renames use create/delete path records; deleting the old path requires the existing deletion switch and an empty folder. Interrupted operations retain a journal and stable operation IDs. Failed pagination, missing known versions, unknown schemas and unsafe paths stop processing.
