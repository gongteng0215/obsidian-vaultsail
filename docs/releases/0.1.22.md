# VaultSail 0.1.22 测试版

> 2026-10-15 更正：本记录中关于“测试版不会更新社区安装版本”的判断不成立。社区安装依据仓库 manifest.json 的版本选择包，GitHub prerelease/Latest 标记不能单独隔离；请以实际安装版本和最新发布说明为准。

减少并发传输中重复的云端目录查询，并显示同步实际耗时。多个文件同时查找同一目录时，共享当前正在进行的完整分页查询；请求结束即释放，不缓存「不存在」，分页异常或权限错误仍会阻断操作，恢复时的强制核验使用新查询。

新上传的内容和版本记录仍完整回读并校验 SHA-256。对本次插件运行中已校验过的相同内容，先重新查询云端，只有文件 ID、服务端摘要、大小、修改指纹全部一致时才复用结果；摘要缺失或指纹变化时重新回读，损坏内容仍会停止发布。云端格式、恢复日志和配对码格式不变。

进度卡片实时显示连接检查、云端扫描（含结束前复查）、本地扫描和传输处理耗时，以及上传相关请求、下载/回读请求的累计耗时、请求总数、令牌刷新次数和失败/限流重试等待。脱敏报告有各类请求的数量、累计/最大耗时及尚未确认结束的原生请求数。并发请求耗时可重叠，不能直接相加作为总耗时。报告不记录 URL、账号、路径、密钥、响应内容或笔记正文，仅保留至插件重载。

133 项自动化测试、类型检查、构建和 ZIP 校验通过。包含分页查询共享、查询失败后重试、新文件可见性、相同内容复用、缺失摘要/内容损坏回退、并发耗时、迟到响应隔离、令牌复用与并发单次刷新，以及界面实时更新。

与 0.1.21 的模拟 API 对比：固定每请求 10 ms、服务同时处理 4 个请求、客户端并发 8、每场景重复 3 次。8 篇不同内容的 1 KiB 笔记，总请求 98 → 84，目录查询 17 → 3，平均耗时 401 → 369 ms；16 篇笔记复用 8 份内容时，总请求 162 → 133，平均耗时 648 → 572 ms。所有恢复内容逐文件 Hash 一致。这不是实际百度网盘测速，真实账号速度与 iPad 表现仍待用户设备验证。

最低 Obsidian 1.11.4，单文件 20 MiB，默认并发 8，保留已有合法并发设置。发布为 GitHub 测试版，社区版本仍为 0.1.17。
