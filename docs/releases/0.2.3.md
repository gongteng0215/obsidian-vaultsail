# 0.2.3 · 电脑端附件传输本地预览

本版修复超过 20 MiB 的 MP4 始终出现在跳过列表的问题，包含本机约 338.65 MiB 的附件。仅供本地测试，社区默认安装目标仍为 0.2.0。

- 电脑实验版单文件默认 512 MiB，在「传输与恢复 → 单文件大小上限」可设 20–512 MiB。旧配置无需重新配置、授权或绑定。
- 本地读取、百度分片上传及回读、远端记录解析、下载暂存、恢复和冲突副本使用同一本机上限。
- 超过 20 MiB 的附件独占传输批次；小文件仍遵循原有 1–32 路并发设置，默认 8。
- 移动端保留 20 MiB。较大文件的有效版本记录可读取，但其正文跳过；保留基线及关联路径，继续其他独立文件。
- 大小配置只属于本机，账号配对不覆盖本机选择；调整上限会使旧预览失效，不清除授权、绑定或任务日志。
- 元数据、状态文件、历史、Markdown 自动合并仍保留原有限制。

## 兼容与限制

**向同一云端库上传超过 20 MiB 的附件前，同库所有设备应更新至 0.2.3 或更新版本。** 旧版操作记录解析器不能接受这些尺寸，会停止扫描。移动端即便更新，本版仍不下载超过 20 MiB 的附件。

仍使用整文件缓冲，上传按 4 MiB 分片构造请求；本版没有实现流式读写、分片断点续传、GB 级附件或更高的移动端上限。调整大小不代表提升百度服务端速度。

## 验证

自动化使用模拟百度接口和 Obsidian 文件接口，不代表真实百度账号或 iPad 验收：

- 实际分配 25 MiB + 17 字节，按 7 片上传、发布记录、下载和中断恢复，逐字节 SHA-256 一致；重复同步不新增版本。
- 插件入口和实际本地适配器使用 21 MiB + 37 字节，覆盖上传、恢复副本、还原、配置变更和凭据/绑定保留。
- 32 路配置下较大附件不与其他传输重叠。
- 20 MiB 客户端跳过较大远端正文、保留其基线，其他笔记继续上传下载。
- 大于 512 MiB 的记录、路径冲突和损坏对象仍阻断相关写入。
- 独立进程的合成百度适配器基准：339 MiB / 85 片及 512 MiB / 128 片上传、发布、下载 Hash 校验通过，均无令牌刷新；观测 RSS 峰值分别约 1766 / 2634 MiB。模拟服务器本身保留额外副本，这不是 Obsidian 内存上限，也不能用其耗时推断真实百度速度。

基准可通过 `node --experimental-strip-types scripts/benchmark-desktop-attachment.mjs 339` 或 `512` 复现；为避免普通 CI 分配巨型缓冲，独立于常规测试执行。本机完整自动化回归 182 项通过。

真机待验：用户本机 MP4 的真实上传、另一台电脑下载及 Hash、内存峰值和长时间运行；iPad 本版仅验证模拟读端隔离，真机结果另行记录。
