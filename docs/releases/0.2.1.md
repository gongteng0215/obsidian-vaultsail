# VaultSail 0.2.1：大文件预检与跳过清单（预览）

本版是大文件方案 L0 的试作，来自 `codex/large-file-preflight` 独立分支。社区默认分支仍使用 0.2.0；仅标记 prerelease 不能隔离社区更新，因此本版不推进默认分支清单。

## 本次变化

- 本地扫描先检查文件大小，超过 20 MiB 时不读取正文，列为跳过项；其他独立笔记继续同步。
- “存在但超限”与“不存在”分开处理，跳过文件不推进基线、不推断删除。
- 超限文件涉及已知身份和远端重命名时，关联路径暂缓应用、删除和改名。有无法校验的大附件时，缺失的非删除基线路径也保守暂缓，避免把未知改名当删除。
- 在「传输与恢复」新增「查看跳过文件」，显示本机最近一次成功扫描发现的超限和关联保护项；有跳过时显示“部分完成”和未传输数量。
- 清单不进入配对导出；脱敏报告仅增加数量，不包含文件名。当前清单在本次插件会话内保留，重载后需重新预览或同步重建；最近任务的跳过数量独立保留。
- 原本已使用百度分片上传，本版改为逐块计算摘要、仅按需构造当前分片请求，不再提前复制全部分片。仍使用完整源缓冲，不宣称已实现低内存流式传输或跨重启分片续传。

## 大小与并发

单文件上限仍是 **20 MiB**。**8 是默认文件并发数，不是上限**，原有设置已支持 **1–32**；在「传输与恢复」→「同时传输的文件数」输入 16 或 32，点击「保存并发数」。已有合法选择保留，默认仍为 8。

逻辑数据批次仍按约 24 MiB 约束，大附件会减少同时传输数量；这不是进程内存硬上限。网络、限流和原生缓冲仍影响实际表现，32 路模拟通过不代表真实百度吞吐或 iPad 内存已通过。

远端 schema、操作记录与大小校验未放宽，不会上传超过旧客户端限制的新内容。若云端已存在超限记录、未知格式或损坏数据，仍停止相关操作；不能把这些错误当成普通本地超限。已有未完成恢复日志仍须先安全恢复或明确结束。

## 验证与安装

168 项自动化检查、类型检查、构建和 ZIP 校验通过。新增覆盖：元数据模拟 1 GiB 而不读取正文、小文件继续、10 次重复远端检查、缩小后重新入队、基线保留、远端改名关联、开启删除传播、已确认删除记录不误报、变化后的预览拒绝、路径碰撞、32 路上传及串行提交、分片乱序请求、实际设置/进度/清单 DOM 与诊断脱敏。

上传分片的检查验证了不调用源缓冲 `slice()`，不是原生进程峰值内存测量。测试使用模拟接口和 DOM；真实 Windows/iPad、百度权限、性能和长时间稳定性仍需本机验证。

最低 Obsidian **1.11.4**。可下载三个插件文件或 ZIP 覆盖安装，保留 `data.json`；关闭再启用 VaultSail，确认版本为 0.2.1。iPad 可在 BRAT 指定 0.2.1。无需重新授权或重新导出有效配对码。本次没有云端格式或本机日志格式迁移。

建议先在测试 Vault 同时放一个普通笔记和一个超过 20 MiB 的附件，确认普通笔记上传、附件列为跳过，缩小后可再次同步。删除保护场景在独立测试库验证，不用正式笔记做破坏性试验。
