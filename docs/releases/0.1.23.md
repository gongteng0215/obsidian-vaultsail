# VaultSail 0.1.23 测试版

修复「没有文件需要传输，云端扫描仍反复下载历史记录」的性能问题。0.1.22 在目录列表缺少有效内容摘要时无法保存可复用的版本缓存，且没有变化的任务结束前仍进行第二轮完整扫描。

现在仅对目录列表缺少摘要的文件批量请求新元数据，每批最多 100 项，逐项核对 ID、路径、大小、完整性和下载地址。新元数据提供有效摘要后，已验证的版本缓存可跨重启复用；新记录首次仍读取并校验。目录和元数据都不给摘要时继续安全回读，不能只靠 ID、时间或大小判定内容未变。

批量获取的下载链接仅在当前连接内存中短暂保存、使用一次，不进入缓存文件或诊断。完整批次缺项、重复、路径/大小不匹配或权限错误均阻断，不当成空库。指纹包含文件 ID，变更和同大小损坏仍触发重新读取。

没有上传、下载、冲突或删除动作的计划，基线停在最初已验证的扫描快照，省去结束前的第二轮扫描；期间稍后出现的新版本由下一次同步发现。实际发生传输的任务仍保留结束前复查。进度卡片和脱敏报告新增扫描轮数、版本缓存命中/枚举数量、实际读取记录数及缺少指纹数。

137 项自动化测试、类型检查、构建和 ZIP 校验通过。新增覆盖 107 条记录的分批元数据与跨重启缓存、异常/缺失摘要批次、7 个无变化文件的冷/热/重启扫描请求预算及后续修改正常发布。

模拟 7 篇内容一致的笔记，目录不返回摘要、元数据返回摘要，包含账号检查，每请求固定 10 ms，重复 3 次：首次扫描 39 → 14 次请求、233 → 129 ms；连续第二次 39 → 6 次请求、236 → 95 ms；重启后 39 → 7 次请求、234 → 109 ms。旧版缓存 0 条，新版缓存 7 条；未发布额外记录，云端内容逐文件 Hash 一致。此结果为接口模拟，并非真实百度或 iPad 测速。

最低 Obsidian 1.11.4，单文件 20 MiB，已有合法并发配置、账号凭据、绑定、配对码及云端格式保留。发布为测试版本，仍需真实设备验证。更正此前说明：社区安装根据仓库清单中的版本号选择 GitHub 安装包，单独设置 prerelease 不能隔离社区更新，也不能据 GitHub Latest 为 0.1.17 判断社区安装版本。更新后以插件实际显示的版本为准。
