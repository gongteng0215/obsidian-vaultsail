# 0.2.4 · 上传进度、同步记录与电脑附件

从社区 0.2.0 升级还将获得 0.2.1–0.2.3 的超限保护、最近 30 次本机同步记录及电脑端附件支持。无需重新授权或绑定。

**兼容：** 同库所有设备先更新至 0.2.4，再上传超过 20 MiB 的文件；旧版读端会停止扫描。电脑默认 512 MiB（可设 20–512），大附件逐个传输，仍是整文件内存缓冲。iPad 等移动端仍为 20 MiB，会跳过更大附件并继续其他独立笔记。尚未实现流式传输或分片断点续传。最低 Obsidian 1.11.4。

此前任务字节数只在整文件校验、发布和基线保存后增加。大视频即便正在上传，也会长时间显示 0 B。本版增加独立的单文件上传进度，保留原有任务完成统计。

- 设置页与传输预览显示文件名、已确认上传字节 / 总字节、百分比、已确认分片 / 总分片及正在发送的分片。
- 准备附件、准备分片、上传、提交云端文件、回读校验和发布版本分别显示。计算分片摘要时让出界面线程，更新准备数量并响应暂停。
- 每片（当前最大 4 MiB）得到成功响应且分片 MD5 匹配后才计数；请求进行中不估算字节。回读使用完整响应，等待时显示明确阶段和等待时间。
- 重试显示新的尝试次数，按本次上传重置分片统计，不累计重复字节。预上传确认已有的分片计入服务端确认数，乱序分片及尾片按实际长度计数。
- 相同内容的并发写入共享网络操作，但每个调用者都能收到自己的进度；不同文件的进度分开显示。界面观察者出错不会打断传输。
- 传输、冲突分支、解决版本和恢复发布共用进度入口。上传 100% 只表示服务端已确认分片，校验并发布记录后才计入任务完成。
- 调整进度不改变云端格式、账号、绑定、文件上限或并发设置。本版按用户确认发布为社区更新。

## 验证

自动化 186 项通过，包括：第二片请求暂停时，界面及引擎已显示第一片的实际字节，文件尚未完成且基线未推进；两文件并发时分别显示自己的字节；乱序尾片、观察者异常、相同对象共享进度、限流重试和错误分片 Hash 不误计数。真实 Obsidian/百度账号的显示和传输速度仍待用户本机验证。

独立的 339 MiB 合成往返基准确认收到 85 次分片字节增长，最终 Hash 一致，令牌刷新 0 次。模拟过程不能代表真实网速或真实设备验收。

## English

Version 0.2.4 adds per-file server-acknowledged upload bars, percentage, slice counts and clear preparation/commit/readback stages. Acknowledgements update after each successful slice, up to 4 MiB; a pending native request has no intermediate socket-byte progress. Upload 100% is separate from verified task completion.

Upgrading from 0.2.0 also includes metadata-first oversized-file isolation, persistent local sync history (30 tasks with search and filters), and desktop whole-buffer attachments up to 512 MiB (configurable 20–512). Large attachments transfer one at a time; other files retain configurable concurrency 1–32, default 8. Settings and authorization are preserved.

Update every device sharing the cloud vault to 0.2.4 before publishing attachments over 20 MiB: older clients reject those records. Mobile remains at 20 MiB and skips larger files. Streaming, resumable slices, comprehensive native iPad validation and real Baidu throughput validation remain pending. Requires Obsidian 1.11.4+.

Validation: 186 automated tests, build/package checks and synthetic 339/512 MiB integrity benchmarks. The 339 MiB upload produced 85 acknowledged byte updates. Simulated checks are not native-device certification.
