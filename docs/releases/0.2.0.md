# VaultSail 0.2.0 自动同步与冲突合并

保存后可自动同步，前台也会定期检查其他设备的新版本。新增统一队列、冲突收件箱、逐块选择、合并草稿和解决版本发布；默认不开启自动同步，升级后在「传输与恢复」主动开启。两台设备都更新到 0.2.0 再测试新合并流程。

本地变动合并等待 2 秒，持续编辑最多合并 15 秒；远端默认每 60 秒检查并加入随机延迟，可设置 30–300 秒。一个库只执行一个任务，文件内部仍按现有设置并发，默认 8。离线、忙碌和限流可能延长等待。手动「开始同步」立即入队，运行中再次点击合并为后续一次任务。

队列、用户暂停和重试时刻按设备及连接隔离保存，不携带正文或凭据。启动、返回前台、索引异常及每 10 分钟完整核验，日常重读脏文件与受远端变更影响的文件；远端无变化时不读取本地正文。下载产生的本地事件与基线核对后消除，不忽略同期用户编辑。后台停止派发并请求暂停，回到前台先核验日志，用户暂停保持暂停。未确认写入或恢复遇到新编辑会停下等待处理。

Markdown 自动合并要求有效 UTF-8、每份输入及输出最多 256 KiB、最多 3000 行，单个差异表最多 200 万单元。有唯一共同祖先且修改兼容时自动发布合并版本；同内容分支也可收敛。重叠修改、并发前置信息、祖先不明确和多个不同内容分支需确认，不做正文语义判断。图片、PDF 及超出预算的文件选择完整版本。

自动合并使用专用逻辑设备目录和由父版本、路径及内容确定的操作 ID；两个设备对同组分支产生同样结果时复用同一条不可变记录。合并的显示时间继承父记录，不参与覆盖决策。普通云端格式仍为 schema 1。

「查看待解决冲突」可查看本机、共同祖先和各云端版本，逐块选择或编辑全文。关闭会保存本机草稿；确认前重新核验，期间有新修改则保留草稿并停止。采用完整版本、手工合并或保留为两篇，都会保留竞争内容并生成引用全部已知分支的解决版本；另一篇是正常参与同步的文件。发布过程中不将关闭窗口误认为已撤销。

并发重命名按最终路径进入待处理列表，其他独立文件继续同步。删除对修改可以选择保留内容，只有删除传播已开启时才提供独立的删除确认。未知格式、损坏对象、不可变记录被改写和不完整分页仍阻断相关写入。账号或绑定变化后自动同步关闭；账号导入保留当前并发和检查间隔，不导入其他设备的队列。草稿位于 `.vaultsail-state/<设备>/drafts/<连接范围>/`，不参与同步和诊断导出。

158 项自动化测试、类型检查、构建和 ZIP 校验通过。覆盖突发 100 次修改、任务中继续编辑、暂停/重启、后台返回时旧请求才结束、限流等待持久化、重载互斥、增量读取、原生文件事件防循环、草稿重开、提交中关闭保护、两设备并发合并复用一条记录、并发改名、明确删除、保留两篇中断恢复和旧文件名重新使用。测试为模拟接口和 DOM；真实百度账号、iPad 内存及前后台行为仍待设备验证。

最低 Obsidian 1.11.4，单文件仍为 20 MiB。旧设备遇到新的复杂重命名解决关系可能安全停止并要求升级。普通笔记、凭据和配对格式保留，有效配对码无需重新导出。

本版已设为社区安装和更新目标。在 Obsidian「第三方插件」检查更新，安装后关闭再启用 VaultSail；iPad 同样可直接通过社区更新。自动同步默认关闭，在「传输与恢复」主动开启。无需卸载、重新授权或重新导出有效配对码。
