# VaultSail 版本规划

[English](ROADMAP.md) | **简体中文** · [功能清单](../README.zh-CN.md#完整功能清单)

规划基线：**0.2.11 本地预览**，更新日期：**2026-10-19**。0.2.6–0.2.8 已实现传输中心、分片并发和紧凑布局；0.2.9 实现扫描性能与本机性能摘要；0.2.10–0.2.11 增加点击即时反馈、自动任务提醒和图标运行/警示状态。见 [自动同步提醒](releases/0.2.11.md)、[点击反馈验证](releases/0.2.10.md) 和 [扫描验证](releases/0.2.9.md)。这些不代表双端真机验收完成。后续阶段按验收推进，不设无依据的发布日期。

## 产品方向与持续边界

让用户用自己的云端账号，可靠地在电脑和 iPad 间同步笔记，正常修改自动完成，存在真实冲突时能看清并处理，出错时有可恢复内容。

- 用户自行配置应用与账号，直接连接服务商，无项目共用私密密钥或开发者同步服务器。
- 每个本地 Vault 独立绑定一个主云端库，设备身份、基线、队列和恢复数据独立。
- 以内容和版本关系决定同步，不用设备时间决定覆盖；未知结果、损坏对象与不完整枚举不能被当作成功或空库。
- 删除默认关闭，冲突先保留内容，配置与凭据排除同步；性能优化不能去掉内容验证。
- 保留现有加密配对、应用配置、正常笔记和手动同步入口。格式迁移必须有预检、备份和恢复路径。
- 中英文 README、功能状态与发布说明同步更新；模拟测试、真实设备验证分别记录。

版本号之间留有空间，允许插入修复版本。新云盘、大文件与加密不会在基础稳定性尚未达标时同时展开。

附件能力已细化为 [大文件同步实施方案](LARGE_FILES.zh-CN.md)。它是条件路线：0.2.x 先修复超限阻断和分片复制，0.3.x 验证平台与读端兼容，0.4.x 通过门槛后才评估上限和分块传输，0.5.x 或以后完善恢复。当前电脑整文件缓冲默认 512 MiB，移动端仍为 20 MiB；桌面通过不代表 iPad 通过，不承诺 GB 级支持。

实施进度：已有 [0.2.1 独立预览](releases/0.2.1.md)，包含本地超限跳过、关联保护、部分完成清单与按需上传分片；168 项自动检查通过，真机待验证，相关能力已包含于社区 0.2.4。其余里程碑不因此标记完成。

另有 [0.2.2 本地预览](releases/0.2.2.md)：本机持久同步记录、实时逐文件状态和筛选，178 项自动检查通过；这不是云端内容历史时间线或旧版本还原，0.5.0 的恢复里程碑仍待实施。

## 0.2.1 / 0.2.x：先把当前版本做稳

### 交付范围

1. 建立当前使用问题清单，记录版本、平台、触发步骤、安全错误与可复现证据；确认原因后做最小修复。
2. 梳理设置页中旧的“实验”“手动”“冲突副本”提示，和 0.2.0 实际自动合并、队列行为一致。
3. 明确显示等待本地防抖、等待云端检查、正在扫描、正在传输、限流重试、用户暂停和需要处理错误，避免“没有变化”和“没有运行”混淆。
4. 核验忙时点击同步、同步中继续编辑、插件重载、断网再连、暂停后返回前台等链路。
5. 验证重复同步不新增版本、不反复生成冲突副本；恢复时不盲目重发结果未知的写入。
6. 只在需要复现问题时增加不含凭据与正文的诊断字段。性能与状态数据优先本地展示，不添加遥测。

### 验收条件

- 自动化基线保持通过；修复涉及的实际失败链有回归用例。
- 本地突发 100 次修改、任务中同一文件再次编辑、重复点击均不会丢待办或启动重叠任务。
- 同一内容连续手动同步 10 次，不产生额外版本；界面能区分实际扫描、跳过与失败。
- 覆盖保存后、云端发布前后、本地应用前后中断，恢复后逐文件 Hash 一致或明确保留冲突。
- 普通内容冲突不阻止独立文件；完整性与格式错误仍阻断不安全操作。
- 有真实环境的问题就记录真实结果；无法访问设备时明确标为待验证，不能用模拟结果关闭真机验收项。

## 0.3.0：iPad 与多库可靠性

### 交付范围

- 在现有配对基础上完成 iPad 原生密钥保存、Web Crypto、文件选择/粘贴与重启恢复验证。
- 明确“仅账号迁移”和“同库同步”结果，改进导入步骤及失败后的重试指引，保留事务回滚。
- 完成前后台切换和旧请求迟到时的任务恢复，显示当前受系统挂起影响的状态。
- 核验两 Vault、两云端库、账号/应用切换、复制配置和旧队列隔离。
- 验证两设备长时间复用授权与刷新令牌的行为；若平台限制共享刷新，先明确边界并设计兼容方案，不隐瞒为偶发网络错误。

### 验收条件

- Windows 与 iPad 各使用两个本地 Vault，分别绑定两个云端库，交叉操作不串库。
- 100 个混合文件完成跨设备上传下载与逐文件 Hash 对比，包含中文、Markdown、图片、PDF、零字节与上限附近附件。
- 20 次前后台切换后，队列和恢复日志可解释，用户暂停不会被自动解除。
- 覆盖拒绝、取消、错误密码、过期码、密钥保存失败、导入回滚、账号变化与实际刷新场景。
- 发布说明列出 Obsidian/iPadOS/Windows 的实际测试版本和剩余未验证项；不承诺 iPad 后台持续同步。

## 0.4.0：扫描与传输性能

### 交付范围

- 分别测量首次扫描、连续无变化、插件重启、单文件变化和批量变化，区分本地扫描、云端扫描与实际传输。
- 在现有缓存和增量读取上评估按设备的发现索引或检查点，减少历史记录枚举与重复读取。
- 索引只作为已验证发现提示，不能用单个可变清单覆盖并发历史；缺失、过期、损坏或分页失败时回到完整验证。
- 根据大附件内存、限流和失败率评估自适应调度，保留用户配置的并发上限与默认 8。
- 展示可解释的请求/缓存统计。格式变化如有必要，先说明旧客户端行为与迁移策略。
- 大附件按 [专题方案](LARGE_FILES.zh-CN.md) 的平台、兼容和内存门槛单独验收，不直接调大常量，也不因性能版本发布而自动解锁。

### 验收条件

- 固定 7、100、1000 文件数据集，分别记录冷启动、热扫描、重启扫描与单文件变化；每组保留至少 10 次重复的请求数、正文读取量、耗时中位数和高分位。
- 数据集、网络环境与服务端限流条件写入记录，模拟与真实网盘结果分开。
- 无变化热扫描不重新下载历史内容，单文件变化不无条件重读全部本地正文。
- 对两个设备同时发布、索引部分写入、缓存损坏和写入超时核验正确性，所有有效版本仍可发现。
- 给出可复现的前后比较；不通过关闭 Hash、父版本或分页校验换取速度，不无依据承诺“秒传”。

## 0.5.0：历史与恢复工作台

### 交付范围

- 在已有云端版本列表、本机恢复点上增加按文件/路径查找的历史时间线。
- 展示设备、版本关系、变动类型和内容预览，时间只用于显示。
- 支持从云端历史选择旧版本恢复：先保留当前内容，再发布新的后继恢复版本，不能改写旧操作。
- 增加删除记录、重命名历史和待恢复操作的清晰入口；批量恢复先预览。
- 提供本地暂存/恢复数据占用统计与可解释的清理预览，仍保护活动日志、草稿和唯一恢复内容。

### 验收条件

- 恢复旧版后，两设备收到同一个新恢复结果；恢复期间继续编辑会停止旧计划并保留内容。
- 图片/PDF 可选择完整版本，不能伪装成可文本合并；删除与改名历史可追踪。
- 批量恢复中断后可恢复或明确结束，不能把未成功条目显示为完成。
- 清理默认只读预览，目标仅限本插件拥有且确认不再需要的数据；不自动永久删除云端对象。

## 0.6.0：同步范围、中英文界面与可访问性

### 交付范围

- 支持用户定义包含/排除规则，提供受影响文件、原因和规则冲突的预览。
- 固定安全排除不可被规则覆盖；被排除文件不作为删除依据，重新包含后重新对账。
- 为已有库修改规则设计一致的范围迁移提示，不默认批量删除另一端内容。
- 提供完整中英文界面与语言选择，集中维护文案与错误消息。
- 改进 iPad 小屏、触控、键盘焦点、屏幕阅读与长路径显示。

### 验收条件

- 覆盖规则优先级、中文/大小写/Unicode、重命名、规则切换、两端规则不同和重新包含。
- 无规则变化时保持现有默认范围，凭据、内部状态、恢复与配对文件不能被纳入正文同步。
- 中英所有入口、错误与确认操作都有文案；窄屏中配对、冲突与恢复流程可完成。
- 未在配对码中引入新偏好格式前，不迁移队列、基线或凭据引用；偏好迁移必须显式选择。

## 0.9.0 RC → 1.0.0：稳定验收

功能冻结，优先修复。至少完成以下记录后再发布 1.0：

1. 两设备、两云端库完成安装、升级、授权、配对、首次合并、自动同步、冲突和恢复闭环。
2. 从 0.1.23 与 0.2.0 的配置、云端数据和本机状态分别升级演练；若未来格式变化，记录预检和恢复办法。旧版无法读取新格式时明确提示，不声称可以无条件降级。
3. 1000 文件代表性数据集运行至少 7 天，涵盖离线双方编辑、重命名、删除对修改、限流、令牌过期、重载与中断恢复；无已知有效版本丢失、串库或凭据泄露问题。
4. 文档列出实际支持/测试平台、大小与合并预算、背景运行限制、数据位置、诊断与恢复操作。
5. 安装包无凭据和笔记，元数据一致，CI 与公开下载校验通过，真实测试结果可与具体版本对应。

RC 失败就继续补丁修复并重跑受影响验收，不以已经上架代替稳定性结论。

## 1.0 后候选池

| 候选功能 | 进入实施前需要解决的问题 |
| --- | --- |
| 第二个云盘（WebDAV / S3 兼容 / OneDrive 等，先选一个） | 实际需求、认证与准入、分页/一致性/限流语义、统一适配器合约验收 |
| 超出大文件专题已验收范围的超大/GB 级附件 | 专题方案的平台与内存门槛仍适用；先证明能力，再决定是否提高支持范围 |
| 笔记端到端加密 | 密钥派生/分发/恢复、元数据泄露边界、既有库迁移、版本兼容与安全评审 |
| 永久清理云端历史 | 所有设备的可达版本与恢复保留策略、离线设备、并发发布、预览与二次核验 |
| 二维码/分段配对 | 加密码长度与容量、离线重组完整性、过期与误导入，不能降低凭据保护 |
| 可选偏好导出与设备展示 | 明确设置白名单；不迁移运行身份、队列或基线，不把历史设备当实时在线状态 |

这些是候选项，没有固定版本或实现承诺。当前不规划实时多人协作、语义/AI 自动裁决冲突、开发者代管密钥、自建账号服务器或 iPad 持续后台传输。

## 每次迭代的执行约定

1. 选择一个里程碑内的最小可验收任务，写明行为变化和兼容边界。
2. 在隔离分支实现，针对实际风险验证；文档修改仅检查内容、链接与一致性，不为凑数量新增测试。
3. 涉及格式先完成迁移与恢复演练；涉及性能保留前后基准；涉及设备明确真机结果。
4. 更新两版 README、规划状态与发布说明，分别列出完成、未完成和已知限制。
5. 用户授权发布后，验证版本清单、安装附件和公开下载，再推进社区安装目标。预览版使用独立分支，不能只靠 prerelease 标记隔离社区更新。

**当前下一步：在本机验收 0.2.9 的连续同步、重启扫描及另一设备修改；修复真实问题后再授权社区发布。后续依次为 0.3.x 双端可靠性、0.4.x 大文件内存与分块、0.5.x 历史恢复、0.6.x 范围与语言体验。**
