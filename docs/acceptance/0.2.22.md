# 0.2.22 Windows / iPad 验收清单

更新：2026-10-20。只在**专用测试库**运行，生产「笔记」和「测试」只覆盖插件三个文件，不自动生成验收笔记。本清单的真机项目均为**待验证**，自动化结果不能代替。

## 1. 准备固定数据

在项目目录执行（目标目录必须不存在，已存在则拒绝写入）：

```powershell
node --experimental-strip-types scripts/acceptance-dataset.mjs generate dist/acceptance-0.2.22 --desktop
```

- `dist/acceptance-0.2.22/vault/`：用于新建专用 Obsidian 测试库的内容。100 个跨端文件：60 Markdown、20 有效 PNG、10 有效 PDF、5 零字节、5 中文/多层路径；另有 10 个空目录节点，包含多层父目录。
- `--desktop` 另加一个确定性的 25 MiB 二进制附件，总文件数变为 101；iPad 的通用文件验收仍为 100，单独观察附件跳过行为。
- `content-hashes.json` 在 vault 外保存逐文件 SHA-256 清单，不放进同步库，不属于脱敏诊断报告。
- 数据集版本固定为 `vaultsail-dual-device-v1`，不随插件版本改内容。测试标记是 60 篇 Markdown 中的一篇。
- 生成器不读取凭据、不调用百度、不覆盖已存在目录。不要把生成命令的目标设为现有库。

电脑可先只读自校验：

```powershell
node --experimental-strip-types scripts/acceptance-dataset.mjs verify dist/acceptance-0.2.22/vault
```

iPad 更新插件后，在命令面板运行 **VaultSail：双端测试数据校验（只读）**。先验证专用标记，再逐文件比较 SHA-256、检查空目录。缺少标记立即停止，不扫描其他笔记。导出只包含固定分类、版本、平台、数量及耗时；不会导出文件名、正文或内容 Hash。

初次互传通过标准为 `markerValid: true`、`passedFiles: 100`、`passedDirectories: 10`，失败分类全部为 0。此校验用于固定初始数据；改名/删除/编辑后应对照各自预期记录，不能把修改后的内容仍要求等于原始 Hash。

## 3. 真实百度性能采样

同一分组必须保持版本、平台、网络、文件数、并发、任务类型和初始化状态一致。7/100/1000 需要各自独立的专用测试库；1000 文件先完成初始化，再测检查，不把初始化时间算进热扫描。生成器的 100 文件数据专用于内容验收，模拟基准自建 7/100/1000 文件样本。

| 数据量 | 无变化检查 | 首次读取 | 重启后检查 | 本地/远端单文件修改 |
| --- | --- | --- | --- | --- |
| 7 / 100 | 每组 10 次 | 每组 3 次 | 每组 3 次 | 分开各 3 次 |
| 1000 | 3 次 | 先初始化，单独记录 | 3 次 | 分开各 3 次 |

每次任务完成、原生请求全部结束后，运行 **VaultSail：保存专项性能报告（不随任务轮转）**。文件保存到已排除同步的 `VaultSail-配置/`，不会因日常 30 条任务轮转丢失。报告包含本轮和最近 30 次白名单摘要；汇总采样只取当前一轮，重启后尚未运行则取最新保存的一轮。

电脑侧将导出报告转为带明确场景的样本（输出文件必须不存在）：

```powershell
node --experimental-strip-types scripts/acceptance-performance.mjs record exported-report.json --case=warm --files=100 --output=samples/warm-01.json
node --experimental-strip-types scripts/acceptance-performance.mjs summarize samples > acceptance-summary.json
```

`--case` 选 `cold / warm / restart / local-edit / remote-edit / browse / browse-repeat`；`--files` 选 7、100、1000。`samples` 需先创建，**每个目录只放同一网络环境的样本**，不同版本/平台/任务类型/场景/文件量由工具自动分组。10 次及以上才计算 P95，小样本报告中位数和范围。报告只输出固定标签和验证过的数字摘要，不复制源文件名或路径。

普通 `report-local-performance.mjs` 的日常历史汇总缺少初始化/网络标签，不能替代上述受控验收。分类请求耗时是**并发累计**，不得相加当作任务耗时。

## 4. English checklist

Generate deterministic fixtures into a **new dedicated directory** using the command above. Open its `vault/` as a separate test vault; the hash manifest stays outside it. The common corpus has 100 files and 10 empty-directory nodes. `--desktop` adds a deterministic 25 MiB attachment; mobile must skip it safely while retaining existing baselines.

On either device run **VaultSail: 双端测试数据校验（只读）**. The marker gate prevents reading unrelated notes. The tool reads only the fixed synthetic corpus, reports file/directory pass counts and fixed failure classes, and never exports paths, content, hashes or credentials. Export the acceptance report separately from rotating history. Initial-transfer success is 100/100 files and 10/10 directory nodes. Edited scenarios have separate expected outcomes.

All native cases above remain **pending**: encrypted pairing without repeat login, both transfer directions, editing during sync, compatible/overlapping offline edits, rename/deletion, empty directories, lost-response recovery, 20 foreground/background cycles, two devices/two vaults, and natural authorization renewal. Automated results do not close these cases. Do not alter a real token's lifetime to claim renewal success.

For performance, save a special report after each completed task and label it with `acceptance-performance.mjs record`. Separate network environments into different input folders. The collector groups by plugin version, platform, task type, initialization scenario and corpus size. At least ten samples are needed for P95; otherwise only median/range are shown. Manual, automatic and recovery tasks must not be mixed. Concurrent request durations are not wall-clock task time. Real Baidu performance is still unmeasured for this preview.
